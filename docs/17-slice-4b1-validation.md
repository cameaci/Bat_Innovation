## Inspection and pre-code review

Read project implementation/design/testing/reuse/evaluation and Slice 3A/4A contracts. Inspected SQLite window plans, evidence fingerprint/epoch validation, immutable histories, current IPC and worker/publication safeguards. Camera_Trap `176451c272628f4f8e38633db747cb427d587072` download helper (blob `712f375e1dbdbbc54aac351b6efbb5833e8e0651`) is a pattern reference only; whole-Blob renderer downloads and its ecology/domain exports do not fit this bounded private export. No code is copied. Python stdlib SQLite backup/csv/Fraction, Node streams and native dialogs supply the implementation.

Five-role challenge: vision requires exact original PTS and independent clocks, no decoder changes; ecology requires separate explicitly provisional observations/all-window audit with unresolved disagreement; desktop QA requires one consistent read-only snapshot, cancellation/restart/write-failure cleanup and dirty-workspace locks; security/licensing requires safe typed CSV cells, ID-only authenticated streaming, fixed MIME/caps and no source paths; maintenance keeps v5 and existing evidence/history validators, without a template framework or service.

Design: a single bounded non-media export worker copies an authoritative read-only SQLite transaction to a private bounded snapshot, then streams two CSVs and a small manifest into a staging directory. The original database, evidence epochs and histories are never written by export. Reconstructed immutable plans account for missing manifest rows explicitly; incompatible plans fail rather than claiming coverage. Current source/PNG validation is read-only and bracketed before publication. A native main-process directory picker saves capped verified files in a fresh folder; renderer/backend never accept a destination path. Completed bundles publish atomically; partials are removed on failure/cancel/quit/restart. Histories are referenced by existing authenticated paginated endpoints with immutable upper revisions from the snapshot.

## User flow and authoritative data

Select a terminal processing run, save or explicitly discard all first-review, QA and timeline drafts, acknowledge the provisional warning, then choose **Export provisional CSVs**. The UI reports actual/planned/missing records, processing/review/QA counts, staleness, observed gaps, evidence warnings, schema, snapshot UTC, file names and byte/row counts. Gallery filters do not affect exports. A second explicit native-directory action saves a fresh bundle; cancelling the dialog saves nothing. No destination or source path, CSV payload or launch token crosses renderer IPC. The four added bridge operations accept a run/job ID only; the authenticated content route accepts one of three fixed kinds.

The bundle contains `provisional-observations.csv`, `technical-window-audit.csv` and `manifest.json`. Schema/column version is `bat-provisional-csv-v1`; Python column lists and the manifest define exact order. All carry the exact requested provisional label, directly in CSV data rows or, for a zero-row observation file, its companion manifest and UI. This is not an approved ecology spreadsheet. No deduplication, final adjudication, ecological presence/absence, species or roost conclusion is supplied.

A read-only authoritative SQLite v5 transaction pins the backup and as-of UTC. The private copy alone is normalized to DELETE journal mode before becoming read-only: SQLite backup otherwise inherits WAL mode and can leave private snapshot sidecars. No original database schema, journal mode, evidence epoch, review or QA value/history is changed by export. Real simultaneous HTTP saves under rollback journalling receive explicit busy responses and succeed after retry; the WAL fixture permits both first/QA writes during the backup while exported projections retain the pinned earlier revisions. Live evidence/coverage changes after the snapshot reject publication with `export_stale`. Saved human decisions are expressly as of the snapshot, not live approval.

Exact plans are reconstructed in source-snapshot order, then window index. Missing stored windows get explicit `missing_manifest_record` rows with exact bounds and no fabricated ID/image. Extra records, changed plans, invalid parameters or a planned-count mismatch fail the export. Observation order is window order then observation UUID; repeats retain order and content except intentional as-of timestamps. Original PTS/timebase and rational signed numerator/positive denominator columns are exact canonical numeric strings. End PTS is exclusive; unknown final endpoints remain blank. Counts stay blank when unknown. Source hashes, algorithm/parameter hashes, output hashes, evidence fingerprint/epoch, quality flags and historical/effective first/QA decisions remain distinct. Historical disagreement/clarification flags survive a later QA decision. Stale or unavailable evidence cannot become current QA agreement.

Clock UTC is blank without an explicit provenance-backed anchor for that same segment, first source PTS and timebase. No filesystem/FPS/other-camera clock is inferred. Fractional offsets use `Fraction`; an ISO UTC field is emitted only when exactly representable at microsecond precision. Otherwise the canonical JSON retains the exact anchor and rational offset with `exact_fractional_offset_only`; no rounding occurs. All snapshot and recording UTC serialization is ISO8601 with a UTC offset.

## Histories and CSV safety

Technical rows carry the existing authenticated first/QA history endpoint and `*_history_through_revision`. Request `?after_revision=0`, follow `next_after_revision` in the existing 50-event pages, and retain only events whose revision is at most the exported cap; stop once the cap is reached. Events added later are excluded. A zero cap means no events. Existing append-only triggers protect those references; this defines history retrieval, not a standalone archival copy of the whole database. Preserve the original database/backup to retain the referenced histories.

CSV uses UTF-8, RFC4180 quoting and CRLF record delimiters, including correctly quoted embedded commas, quotes and multiline text. Every nonempty **text** value starts with one apostrophe, regardless of its first character. Within it, backslashes double and C0/DEL controls except CR/LF become literal ASCII `\uXXXX`. Decoding is reversible: remove exactly one leading apostrophe; decode doubled backslash and `\uXXXX` in one left-to-right pass. Empty text stays empty. Headers are fixed trusted identifiers. Test cases include `=`, `+`, `-`, `@`, leading whitespace/tab/CR/LF, quotes, apostrophes, NUL/DEL, literal backslash escapes and Unicode. Numeric fields accept only canonical signed integers (or blank for unknown), never expressions; PTS are not apostrophe-prefixed or rounded for display safety. Each row's safely encoded `canonical_json` preserves typed booleans, nulls, exact PTS/rational strings and original text. Use that representation or integer/rational-aware software when spreadsheet number precision is insufficient. No `eval`, macros, formula engine or formula execution is used. Actual Microsoft Excel/Windows import execution remains unverified; parser/neutralization tests establish the documented encoding contract only.

## Resource and publication bounds

One export worker and one content delivery are active at a time; native saves are serialized. The existing v5 limits remain 64 source segments, 2,000 planned windows and 100 current observations per window. Each CSV is limited to 50,000 rows, 8 MiB and 64 KiB per encoded row. Manifest is at most 64 KiB; whole database snapshot main file is at most 64 MiB, including unrelated histories. Oversized data fails explicitly; no row truncation. Backup uses 64-page steps; live evidence digest reads 128-row pages; CSV output writes one row at a time. Only bounded plans/fingerprints and one window's observations are retained, not every row or full histories. Image verification reads at most the existing 4 MiB PNG cap.

The Linux worker installs parent-death SIGKILL and hard limits before importing native media libraries: 1 GiB address space, 15 CPU seconds, 64 MiB per file, no core dump. Worker wall budget is 30 seconds, supervised at 32 seconds with kill/wait. SQLite may temporarily duplicate bounded snapshot pages in its private journal/WAL during backup; there is no whole-volume quota. Disk full/write/rename errors fail, and managed stages are removed. Native HTTP transfer uses backpressure and 64 KiB buffers, verifies exact MIME, length, byte cap and SHA256, and has a 30-second bundle transfer deadline. At most 16 MiB plus 64 KiB of final files are published per bundle. These are configured/enforced bounds, not a peak-RSS or full-disk/power-loss performance benchmark.

Backend UUID staging directories publish by same-directory rename only after CSVs/manifest fsync and a final evidence check. Snapshot files are removed before publication. Cancel/failure/normal quit reaps the worker and removes managed files; restart clears only owned UUID stages/bundles. Main-process saves use exclusive fixed files in a private sibling stage and reserve a fresh random directory, then atomically rename the whole bundle. Existing destinations/originals are never overwritten. A fsynced atomic intent record supports restart cleanup; an interrupted intent write precedes any output-directory mutation. Empty reservations/stages are removed, while nonempty atomically completed bundles are retained. Destinations inside the repository or application data are rejected. Permission loss or inaccessible destination storage can require restoring access before recovery; no cleanup deletes originals.

Explicit errors include `export_busy`, `export_too_large`, `export_stale`, `export_write_failed`, `export_schema_required`, `export_missing`, `export_cancelled` and `export_limits_unavailable`. No arbitrary backend error text or paths cross the desktop boundary. Export process limits fail closed outside Linux; existing preview/summary Windows safeguards are unchanged.
