## Windows containment design to prove

Keep preview/summary disabled. Include import in the same safety gate; it is native media processing too. The smallest candidate is one disposable worker per operation and an owned Windows Job Object boundary, not a multiprocessing framework or a signal-name substitution.

1. Create a fresh non-inheritable job handle, configure limits, launch the child **suspended**, assign it, then resume. Assignment/nesting/setup failure must terminate/reap the suspended child and return an explicit unavailable-limits error. Native codecs must never run during an assign-after-spawn race; no breakaway fallback.
2. Enforce per-process/aggregate committed memory, cumulative CPU time and active-process count; maintain a monotonic parent wall deadline and one codec/BLAS thread. Working-set size is not a hard allocation limit, and CPU rate throttling is not cumulative CPU time. Existing Linux budgets (1 GiB address space, preview 20 CPU/25 wall seconds, summary 300 CPU/600 wall seconds) are comparison points, not validated Windows settings.
3. Use `KILL_ON_JOB_CLOSE`, owned termination and bounded waits before releasing the activity reservation or deleting output. Worker-job handles must not be inherited into the children they protect. An outer launcher-owned backend-tree job or equivalently tested ownership is needed for Electron/backend crash; abrupt Node child termination alone is insufficient. Add a narrow graceful shutdown control before the bounded forced-job fallback, preserving dirty-close confirmation.
4. **Storage remains a separate unresolved hard blocker.** Job Objects have no `RLIMIT_FSIZE` or aggregate scratch-capacity equivalent. Preserve logical output/frame/dimension/run/global quotas and metadata reserve, then prove bounded codec sinks and a capacity-enforced scratch strategy. Free-space polling and I/O throttling are not hard capacity limits. NTFS per-user/volume quotas are not per-worker and must not be silently enabled on a survey volume.
5. Prove ACL/reparse confinement, Windows sharing violations, allocated reserve, atomic publication and safe error mapping/restart. A Job Object is not a filesystem/network sandbox. Retain read-only originals, protocol restrictions, token-stripped worker environments and ID-only APIs.

## Native acceptance procedures and next steps

Every procedure is **not run**. Stage B needs actual Windows 10/11 x64 machines; record edition/build, architecture, standard-user privileges, CPython/Electron/SQLite/linked FFmpeg versions and exact commands. A green command whose native scenarios were skipped is a failed acceptance gate.

- **W1 - approve and stage:** runtime/licensing owner resolves the binary issues below, fixes the interpreter/artifact closure and chooses a pinned packager. Stage only approved checksummed inputs privately on a clean native machine. Do not borrow installed Python/ffmpeg or download at first launch. Keep binaries/media/outputs outside this public repo.
- **W2 - boot and boundaries:** after a reviewed fixed-runtime resolver exists, disable networking before first start; exercise missing/corrupt runtime files, UI/API boot, token rotation/401, occupied port, strict preload/CSP, normal Chromium sandbox and local app-data ACL/reparse policy. Record actual outbound attempts, not just a screenshot.
- **W3 - real import:** click the actual native picker/cancel using tiny deterministic CFR MP4, nonzero-origin MTS and irregular-PTS MP4. Compare exact original PTS/timebases and SHA before/after. Test denied, missing, changed, read-only, Unicode/space/long-path and removed-drive cases. Import remains a controlled lab investigation until its containment gate passes.
- **W4 - enforce and terminate:** before enabling media, inject job setup denial, memory commitment, CPU spin, child spawn, disk limit, codec/read hang and startup/cancel races. Query native limits/accounting; cancel, close/Keep editing, Ctrl+C, Task Manager kill of Electron/backend/worker and restart must leave zero owned workers, released reservations and explicit interrupted records. Process inspection must use owned handles/creation identity, not port/name killing.
- **W5 - evidence and persistence:** prove exact marker seeking, 30/30/5 coverage and final partial windows, retained weak synthetic motion and all failed/incomplete rows. Exercise locked source/part/target/database handles, junctions, ENOSPC/rename failures, concurrent audit actions and interrupted commits. Reopen with SQLite integrity/foreign-key checks, unchanged audit replay/projection and unchanged originals. Record actual journal mode; test WAL sidecars only if a later design explicitly selects WAL.
- **W6 - install lifecycle:** on clean native machines test offline install, restart/update/uninstall, original preservation and explicit local DB retention. Disclose unsigned lab-build Defender/SmartScreen behavior; do not present an unsigned smoke build as a generally trusted installer.
- **W7 - first usable beta decision:** independent review confirms W1-W6, safe import/preview/summary and source-verified manual review. Release/IT approves a private distribution channel and exact notices/compliance materials. Only then offer an internal beta. Ecological QA/export and production Slice 5 work remain separately scoped.

First follow-ups should therefore be: allocate native lab machines and resolve codec distribution policy in parallel; remove the unused CLI startup prerequisite in a small tested change; implement/review bounded inspection and the Windows process/storage boundary; then prove the fixed offline layout and installer lifecycle. Do not start with an installer that merely wraps the current rejected/unbounded runtime.
